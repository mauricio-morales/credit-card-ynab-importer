# Implementation Plan: Scotia/DaviBank XLSX Import

**Branch**: `004-scotia-xlsx-import` | **Date**: 2026-08-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/004-scotia-xlsx-import/spec.md`

## Summary

Scotia/DaviBank switched their credit-card statement export from `.xls` to `.xlsx`, which the importer's `davi_stage1.py` (built on `xlrd`, which cannot read `.xlsx`) can no longer process. This plan replaces the Stage 1 file-reading layer with `openpyxl`, keeps the six-column schema, card-section markers, and skip-row rules unchanged (verified against the real reference file `Scotia Visa.xlsx`), adds a clear rejection path for legacy `.xls` files and unreadable/malformed `.xlsx` files, and updates the orchestrator/TUI file-selection routing accordingly. Stage 2 and Stage 3 are untouched — this is a Stage 1 + routing + fixtures change only.

## Technical Context

**Language/Version**: Python 3.9+ (unchanged)
**Primary Dependencies**: `openpyxl>=3.1` (new, replaces `xlrd>=2.0.1`); `xlwt>=1.3` (fixture-generation-only dependency) is dropped since fixtures move to `.xlsx`
**Storage**: N/A — flat files (`.xlsx` input, intermediate/final `.csv` outputs written alongside the input file)
**Testing**: `pytest>=7.0`, semantic fixture-comparison pattern already used by `tests/test_davi_pipeline.py` / `tests/conftest.py`
**Target Platform**: macOS CLI/TUI (personal tool, existing `scripts/orchestrator.py` + `tui/` Textual app)
**Project Type**: Single project (existing `scripts/` pipeline stages + `tui/` Textual UI + `tests/`)
**Performance Goals**: N/A — statements are tens to low hundreds of rows; sub-second processing, unchanged from `.xls` behavior
**Constraints**: Zero change to intermediate/final CSV output format, field values, or file-naming convention (Constitution Principle II, IV); must not regress the BAC (`.csv`) pipeline
**Scale/Scope**: Single-user personal finance tool; one bank pipeline (DaviBank/Scotia) affected

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| Constitution's Technical Stack section (`xlrd` for `.xls`, "`.xls` is the only supported DaviBank format") is now inaccurate and must be amended. | The bank (Scotia/DaviBank) unilaterally discontinued `.xls` exports in favor of `.xlsx`; the tool cannot import *any* current statement without switching libraries and the supported-format list. This is a forcing function outside the project's control, not a design preference. | Keeping `xlrd`/`.xls`-only as documented and refusing to support `.xlsx` would make the tool permanently unable to import new statements — not a viable alternative. Supporting both `.xls` (via `xlrd`) and `.xlsx` (via `openpyxl`) indefinitely was considered and rejected (research.md §1) since `.xls` files no longer exist in practice going forward — carrying that parsing path forever would itself violate Principle V (Simplicity/YAGNI) for a format with zero remaining producers. |
